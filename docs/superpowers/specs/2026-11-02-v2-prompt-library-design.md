# v2 — 프롬프트 저장소 (설계 초안)

작성일: 2026-11-02 · 상태: 브레인스토밍 중간 정리 (구현 승인 전)

## 1. 의도와 이유

인스타그램에 릴스와 카드뉴스로 프롬프트를 공유하고 있다. v2는 그 게시물에 나온 프롬프트를 사이트에서 다시 찾아 쓸 수 있게 하는 **프롬프트 저장소**다.

사이트의 진짜 목적은 **Gemini 학생 혜택 가입**이다. 저장소는 사람들이 오게 만드는 미끼이고, 가입 안내는 그 옆에서 가볍게 건네는 넛지다. 즉 프롬프트가 주인공, 혜택 안내가 조연이다.

## 2. 목표 / 비목표 / 안티 목표

**목표**
- 릴스·카드뉴스에서 본 프롬프트를 번호로 바로 찾는다.
- 게시물에 없는 프롬프트와 인터넷에서 많이 쓰이는 일상 프롬프트도 함께 보관한다.
- 프롬프트를 열면 내용뿐 아니라 어떤 기능인지, 어떻게 쓰는지까지 알려준다.
- Gemini 학생 혜택 안내를 부담 없이 노출한다.

**안티 목표 (이러면 실패)**
- 가입해야만 다른 기능을 쓸 수 있는 구조. 프롬프트 열람과 복사는 가입·로그인 없이 가능해야 한다.
- 광고처럼 보여서 프롬프트만 가져가고 나가버리는 느낌.

**비목표**
- (이번 정리에서 정하지 않음 — 7번 미정 항목 참고)

## 3. 화면 구조

모바일 우선. 손그림 시안 기준.

**메인(목록)**
- 상단 제목 "프롬프트 저장소", 그 아래 탭 4개: **릴스·카드뉴스 / 카테고리 / 랭킹 / 기타**
- 탭 아래 검색창
- 본문은 카드 격자(2열 기준, 큰 화면에서는 3열). 카드 = 큰 썸네일 + 제목 + 복사 횟수. 썸네일 위에 "릴스 #12" 같은 번호 배지.
- 카드에는 복사 버튼을 두지 않는다. 카드를 누르면 상세로 간다.
- 맨 아래에 Gemini 학생 혜택 안내 띠 한 줄.

**탭별 내용**
- 릴스·카드뉴스: 게시물 번호로 찾는다. 릴스/카드뉴스 구분과 번호가 보인다.
- 카테고리: 레포트, 시험공부, 발표, 일상 등으로 거른다. 카테고리 이름은 제안값이며 확정 아님.
- 랭킹: **오늘 / 이번 주 / 이번 달** 인기 프롬프트 TOP 5. 인기 기준은 **복사 버튼을 누른 횟수**.
- 기타: 내용 미정.

**상세**
위에서 아래로: 큰 이미지(릴스·카드뉴스 원본 게시물 링크 포함) → 제목 → "어떤 기능이에요?" → "이렇게 쓰세요"(단계) → 프롬프트 본문 + **복사하기 버튼** + 복사 횟수 → 혜택 안내 띠. 상세에서 목록으로 돌아올 수 있다.

## 4. 시각 방향

- **Gemini 느낌의 다크모드.** 거의 검정 바탕 + 파란 계열. 색 조화가 핵심.
- 파란 한 줄기: 진한 남색 → `#1a73e8` → `#4285f4` → `#8ab4f8` → `#c2e7ff`. 흰색/회색 텍스트. 따뜻한 색은 이미지 가장자리의 아주 얇은 빛 정도로만.
- 둥근 모서리 타일, 알약 모양 탭과 버튼, 얇은 선 아이콘.
- 모션 그래픽: 타일 이미지 속 원형 빛이 천천히 떠다니는 정도. 과하지 않게.
- 레트로(초기 컴퓨터 창, 파일정리함, 픽셀)는 **폐기**했다. 한때 탭을 폴더 이름표로 하자는 안이 있었으나, 최종 방향은 다크 Gemini 톤이고 탭은 알약형으로 한다(제 판단, 확인 필요).
- Google·Gemini 로고나 공식 이미지는 쓰지 않는다. 분위기만 따른다.
- 시안 파일: `.superpowers/brainstorm/866-1793604945/content/gemini-dark.html` (브라우저로 열면 확인 가능, 커밋 대상 아님).

## 5. 데이터와 동작 (제안)

- 프롬프트 한 건: 제목, 본문, 기능 설명, 사용 단계, 카테고리, 출처(릴스/카드뉴스 + 번호 + 인스타 링크, 없을 수 있음), 썸네일, 복사 횟수.
- 복사 횟수를 일/주/월로 집계해야 랭킹이 가능하다. 현재 사이트에는 방문자 행동을 저장하는 곳이 `apps-script/Code.gs`(응모 저장)뿐이라 **집계 저장소는 새로 정해야 한다**(빌더 판단).

## 6. 제약

- 기존 스택 유지: Next.js(app router) + Tailwind v4, Pretendard 글꼴.
- 개인정보: 복사 횟수 집계는 개인을 식별하지 않는 카운트만 쓴다. 기존 개인정보 처리방침과 어긋나지 않게 확인한다.
- 가입 안내는 열람/복사를 막지 않는다.

## 7. 아직 정하지 않은 것 (사용자 확인 필요)

1. **썸네일**: 실제 릴스·카드뉴스 표지를 그대로 쓸지, 시안처럼 모션 그래픽 타일로 새로 만들지. (제 가정은 표지 사용이었으나 다크 톤과 어울릴지 미확인.)
2. **기존 15분 강의 코스**(`/learn`, `/quiz`, `/done`, 경품 응모)는 v2에서 어떻게 할지. 첫 화면을 저장소로 바꾸면 코스 진입점이 필요하다.
3. 기존 **기능 사전**, **프롬프트 빌더**, **Gem 템플릿**은 유지/통합/폐기 중 무엇인지.
4. "기타" 탭에 무엇을 넣을지.
5. 카테고리 최종 목록.
6. 초기 프롬프트 개수와 입력 방식(코드 안 파일 vs 외부 시트). 지금은 몇 개 없음.
7. 탭을 알약형으로 한 것(제 판단)과 폴더 이름표 요소를 일부 남길지 여부.

## 8. 빌더에게 맡기는 것

- 집계 저장소 선택, 컴포넌트 분리, 모션 구현 방식, 접근성(움직임 줄이기 설정 대응 포함), 반응형 세부 간격.

## 9. 대화에서 확정한 사항 — 2026-11-02

이 절은 위 초안의 미정 항목과 충돌하는 내용을 대체한다. 사용자가 1단계 구현을 승인했다.

- Gemini 모바일 웹 다크모드를 UI·UX 참고로 사용한다. 공식 로고·이미지는 사용하지 않는다.
- 15분 강의와 프롬프트 빌더는 유지하며 기타 탭에서 연결한다. 경품 응모는 종료한다.
- 기능 사전의 설명은 상세로, Gem 템플릿은 저장소 항목으로 통합한다.
- 썸네일은 혼합형: 게시물 표지가 있으면 사용하고, 없는 항목은 그래픽 타일을 사용한다.
- 카테고리: 레포트·과제 / 시험공부 / 발표 / 일상.
- 콘텐츠는 코드 파일로 시작한다. 데이터 접근 계층을 분리해 추후 외부 시트로 교체한다.
- GitHub Skill은 사용자가 자기 Gemini에 가져가 쓰는 방식이다. 도입할 원본, 재배포 조건과 Gemini 호환성은 항목별 확인한다. 별도 카테고리를 추가하지 않는다.
- 복사 집계는 Google Sheets + Apps Script를 사용한다. 응모 데이터와 분리하고, 한국 시간 기준 날짜·프롬프트 ID·횟수만 저장한다.
- 개발 단계: ① 목록·상세 UI ② 콘텐츠·복사·MD 제공 ③ 집계·랭킹 ④ 기존 기능 정리.

### 1단계 구현 범위

- `/`: 검색, 출처 필터, 카테고리, 랭킹 준비 상태, 학습·도구 진입점.
- `/prompts/[slug]`: 이미지, 설명, 사용 단계, 본문, 복사, Gemini 연결, 목록 복귀.
- 기존 빌더 프리셋 5개와 Gem 템플릿 3개를 활용한다. 게시물 번호·표지·인기 수치는 임의로 생성하지 않는다.
- 복사 기능은 사용 가능하지만 서버 집계는 아직 연결하지 않았다. 횟수는 `null`로 구분한다.
- 외부 Skill 수입과 MD 다운로드, 실제 집계, 기존 강의의 경품 문구·응모 API 종료는 후속 단계에 남아 있다. 이번 단계는 로컬 미리보기이며 배포하지 않았다.
